# OAP — этап 0: квалификация самостоятельного протокола (19.11.2026)

**Статус:** `RESEARCH_DRAFT / NOT_NORMATIVE / NON_AUTHORIZING`.

**Решение руководителя:** разрабатывать самостоятельный Open Authorization Protocol, а не переименовывать или незаметно расширять UU-AAP. Рабочее сокращение `OAP` НЕ утверждено в качестве уникального публичного имени.

**Источник среза:** `Matawaka/uu-aap`, main `8ff0fd01514f7d8bcfc2fb96d794b790b904bafc` (18.11.2026). Источники и пределы обзора — [QUALIFICATION.md](QUALIFICATION.md).

## Что подтверждено

- В UU-AAP Core v0.1 уже отделены observation, intent, authority, coordination, ActionPermit, ActionReceipt и OutcomeReceipt. Core — экспериментальный кандидат, не полномочие в реальном мире.
- Есть scoped-authority-evidence, pre-action admission и invocation/action-receipt binding, но их проверка не заменяет независимое доказательство правомочности issuer, действительного разрешения и конечного эффекта.
- Есть JSON CLI и локальный MCP для **синтетических** Personal Anchor испытаний; `READY` и успешная replay-проверка не доказывают личность или авторизацию.
- Действующий обзор рынка от 16.11.2026 уже не считает уникальными gate, scope, consent, audit trail, одноразовое approval и временные ограничения.
- Существует значительное пересечение с OAuth/GNAP, AuthZEN, AAuth и открытыми протоколами сторонних разработчиков. Название OAP занято как минимум другими инициативами.

## Предлагаемая самостоятельная граница

Открытый, provider-neutral **Authorization-to-Effect Evidence Interoperability**: переносимые типизированные связки «подтверждение полномочия → решение → одно конкретное разрешённое действие → доказательство попытки/факта исполнения → наблюдение результата», проверяемые независимыми участниками. OAP сам по себе НЕ является IdP, PDP, органом выдачи прав, агентом, исполнителем, журналом истины, платформой контроля личности или доказательством юридической ответственности.

Основные кандидаты на сообщения: `AuthorityReference`, `ActionRequest`, `DecisionEvidence`, `ActionPermitBinding`, `InvocationEvidence`, `OutcomeObservation`, `RevocationStatus`, `VerificationResult`. Это проектные понятия; ни поля, ни форматы, ни криптографический профиль пока не нормативны.

## Предварительный вердикт

**GO для разработки нормативной модели и conformance-suite; NO-GO для заявления о готовом открытом стандарте, production-сертификации или независимой совместимости.** Доступные тесты уже дают хорошее основание для проектирования, но отсутствует квалифицированная реализация OAP двумя независимыми стеками с проверкой реального enforcing boundary.
