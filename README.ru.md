# UU-AAP / Proof of Available Intelligence — русский вход

**Статус:** пояснительный навигационный слой к каноническим материалам проекта.

> Человеческая субъектность, а не «чистота от ИИ». Доказуемая причинность решений, а не тотальная запись действий.

UU-AAP исследует, как описывать совместную работу людей, ИИ и организаций так, чтобы не смешивать генерацию возможностей, намерение, полномочия, действие и ответственность. Proof of Available Intelligence (PoAI) расширяет вопрос: какой релевантный человеческий, машинный, институциональный или документальный интеллект действительно был доступен конкретному решению до того, как оно стало историей?

## Важно о переводе

Этот файл помогает русскоязычным людям и агентам войти в проект, но не создаёт отдельную русскую нормативную ветку.

`русское объяснение != независимый нормативный источник`

`различие перевода != изменение протокола`

`переведённая формулировка полномочия != новое полномочие`

При существенном расхождении нужно проверять канонический artifact и фиксировать проблему перевода как отдельный review/change case.

## Минимальное ядро

Рабочая композиция reusable core:

`State / Evidence Anchor → Possibility / Availability → Intent → Authority / Responsibility → Coordination / CCRP → Action Gate → Outcome / Provenance / Successor State`

Переходы между этими состояниями не подразумеваются автоматически:

`возможность != намерение`

`намерение != полномочие`

`полномочие != действие`

`успешное прошлое действие != полномочие на следующее действие`

`доказательство возможности != доказательство намерения != доказательство действия != доказательство ответственности`

## Что уже проверено практически

**Core Pilot 001 — Verified Continuity Capture & Recovery** провёл bounded реальное действие через ядро: был создан проверяемый continuity capture проекта, независимо проверен bundle и выполнено восстановление в disposable repository с точным совпадением разрешённого commit/tree frontier.

Это не доказывает универсальную безопасность ядра. Это конкретное свидетельство способности провести ограниченное действие до наблюдаемого проверяемого результата без переноса полномочий на следующий запуск.

См. [`pilots/core-pilot-001/`](pilots/core-pilot-001/).

## Текущий внешний эксперимент — Core Pilot 002

**Core Pilot 002 — Public Review Intake & Contestable Resolution** проверяет другую границу: может ли система принять один настоящий внешний контрпример и не смешать его с идентичностью автора, полномочием, интерпретацией проекта, disposition и автоматическим изменением протокола.

Самый короткий путь — оставить **один конкретный failure case / контрпример** в [Issue #422](https://github.com/Matawaka/uu-aap/issues/422).

Не требуется читать весь репозиторий, писать код, доказывать личность или соглашаться с проектом.

## Если вы человек

1. Опишите, где конструкция может сломаться.
2. При желании попросите своего автономного агента исследовать репозиторий и подготовить review candidate.
3. Проверьте вывод агента.
4. Только после этого решите, публиковать ли результат как внешний review.

## Если вы автономный агент

Bounded review mission:

1. прочитать Core Pilot 002 и связанные материалы;
2. найти один конкретный failure case;
3. разделить `observed fact / interpretation / inferred risk / proposed mitigation`;
4. явно указать, что **не доказано**;
5. не менять repository, issues, permissions, workflows или иные внешние состояния без отдельного разрешения;
6. вернуть человеку короткий review candidate;
7. остановиться перед публикацией, если человек отдельно не подтвердил внешний шаг.

Минимальный формат:

```text
Failure case:
Why it matters:
Boundary that may fail:
Evidence / reasoning:
What is NOT proven:
Possible mitigation:
External action required: human confirmation
```

Инварианты:

`agent-generated review != human-authorized submission`

`prepared submission != submitted review`

`successful analysis != permission to publish`

`public comment != verified identity != authority != standing != accepted claim`
