# Witness operator-origin corroboration v0.1

This additive successor consumes merged #942 without rewriting it. It asks a narrower question than legal/operator identity: whether each frozen public operator label has a distinct operator-origin or operator-attributed public source that corroborates the label-to-witness/about relation.

The first bounded profile intentionally admits no separate operator-origin source for `rgdd`, so `5/6` is an informative accepted outcome rather than a CI failure. The Witness Network table remains predecessor/discovery evidence and cannot satisfy the new gate.

Special case: Mullvad's original participation request contained a wrong key type/vkey. The profile requires both the original operator/about relation and a later public correction carrying the accepted exact vkey. Historical error is preserved rather than silently rewritten.

Non-claims remain fail-closed: operator-origin attribution is not legal identity, cryptographic identity binding, legal control, independence, current activity, non-equivocation, C2PA completeness, trusted time, truth, authority, canonicality, maliciousness, or remediation authority.
