## Question

P0.7 asks:

> Can a consumer receive currently valid provenance evidence and still draw an unsafe stronger conclusion that the provenance layer does not establish?

The accepted semantic path is:

```text
fresh source asset
        ↓
official C2PA test signing
        ↓
official C2PA validation
        ↓
Valid / Trusted development-test provenance state
        ↓
consumer interpretation overlay
        ↓
UU-AAP semantic-boundary evaluation
        ↓
safe PASS or unsafe REJECT
```

A C2PA-valid asset is allowed to coexist with a failed semantic interpretation. That is the target observation.

## External tooling anchors

`tooling-baseline.json` pins exact public upstream frontiers.

### `contentauth/c2pagen`

Pinned SHA:

`23c2d4c317bbbb5b049c11cc6d8e85a4729704df`

The project describes itself as a CLI for generating reproducible C2PA assets for testing and benchmarking. P0.7 uses only `small-png`.

The pinned generator uses `c2pa 0.85.2`. Its embedded Ed25519 certificate chain is explicitly `FOR TESTING_ONLY`; the leaf validity extends through August 2030.

### Discovered signed-preset validation frontier

The first live P0.7 run revealed that `small-png-signed.png` generated by the pinned `c2pagen` frontier is **not** an acceptable C2PA base for the semantic experiment.

The source fixture used by `Simple::sign` is pinned as:

`tests/fixtures/simple_manifest.json`

Git blob:

`c3eec4c28045e99c322d3ec148c22c34e1081837`

It contains:

```json
{
  "label": "c2pa.actions.v2",
  "data": {
    "actions": [{ "action": "c2pa.opened" }]
  }
}
```

and declares no ingredient assertion.

Current official `c2patool v0.27.16` (`c2pa 0.90.16`) rejects the generated signed preset with:

```text
validation_state = Invalid
failure = assertion.action.ingredientMismatch
```

P0.7 does **not** add this failure to a tolerance list and does not reinterpret the asset as valid.

To distinguish generator-state evidence from validator-version drift, CI also validates the exact same generated signed preset with the version-matched official validator:

```text
c2patool v0.26.62
c2pa 0.85.2
release commit 0f71dd0ea913d2cdc3daec66642fdfa9a06362f9
```

`classify-c2pagen-signed-preset.js` produces a separate frontier receipt. The currently expected classification is:

```text
SIGNED_PRESET_INVALID_MATCHING_AND_CURRENT
```

This expectation is fail-closed. If the matched validator accepts the preset, or either validator changes behavior, CI fails and the frontier must be reclassified.

Invariant:

```text
generator signed preset != accepted semantic base when validation fails
```

### Accepted semantic base

The semantic experiment still uses a real `c2pagen` output, but it does not launder the invalid signed preset.

CI takes the **same freshly generated unsigned** `small-png.png` and signs it independently with pinned current official `c2patool` using the standard development/test signing path:

```text
c2pagen-generated small-png.png
        ↓
c2patool v0.27.16 test signing / digitalCapture
        ↓
strict C2PA validation
        ↓
Valid | Trusted required
        ↓
semantic corpus may run
```

The existing P0.1 `assertLiveC2paReport` helper remains the gate. Non-tolerated validation failures stop the semantic experiment.

This preserves three different facts instead of collapsing them:

```text
c2pagen can generate the source asset
c2pagen signed preset has its own validation frontier
a separately valid C2PA asset is required before semantic testing
```

## Five semantic adversarial cases

`corpus-v0.1.json` contains paired unsafe and safe consumer interpretations.

### 1. Signer display `Author` -> authorship

Unsafe:

```text
C2PA signer display = Author
-> UU-AAP author
```

Reject: `I1_SIGNER_NOT_GOVERNANCE`.

Safe: signer provenance remains visible while authorship is independently attested.

### 2. Human-validated AI disclosure -> responsibility

Unsafe:

```text
C2PA AI disclosure: human_validated
-> responsible actor
```

Reject: `I4_AI_DISCLOSURE_NOT_AUTHORITY`.

Safe: AI disclosure remains process evidence; responsibility is independently scoped.

### 3. Ingredient title `Original Concept` -> concept origin

Unsafe:

```text
C2PA ingredient title = Original Concept
-> UU-AAP concept origin
```

Reject: `I3_INGREDIENT_NOT_CONCEPT_ORIGIN`.

Safe: artifact genealogy and intellectual genealogy remain separate.

### 4. Action text `approved` -> publication authority

Historical P0.1 rule `I2_ACTION_NOT_DECISION` does not directly target publication authorization, so P0.7 adds one local successor rule:

`P07_ACTION_NOT_PUBLICATION_AUTHORITY`

The historical `rubric-v0.1.json` is not modified.

Unsafe:

```text
C2PA action/display = approved
-> UU-AAP publication authorization
```

Safe: action provenance remains visible; publication authorization is independently scoped.

### 5. Repository/integrity -> `Verified True`

Unsafe:

```text
repository receipt + valid integrity
-> epistemic truth / Verified True
```

Reject:

- `I5_RECEIPT_NOT_TRUTH_REVIEW_AUTHORIZATION`;
- `I6_INTEGRITY_NOT_TRUTH`.

Safe: repository presence and integrity remain separate from factual verification.

## Acceptance

P0.7 passes only if all of the following are true:

1. the pinned `c2pagen` source and tool roles are reproduced exactly;
2. the `c2pagen` signed-preset validation frontier is classified explicitly and no validation failure is tolerated;
3. a valid C2PA base is created from the same freshly generated unsigned PNG and passes strict validation;
4. all five unsafe semantic interpretations are rejected;
5. all five safe paired interpretations pass;
6. semantic evaluation does not mutate or replace the C2PA validation result;
7. no aggregate trust/compatibility/confidence score is introduced;
8. `protocols/core/**` remains untouched.

## Non-effects

P0.7 does not:

- redefine C2PA conformance;
- register a UU-AAP C2PA namespace;
- treat `assertion.action.ingredientMismatch` as tolerated;
- call an invalid signed preset valid;
- convert signer identity into authorship;
- convert AI disclosure into responsibility;
- convert ingredient names into concept origin;
- convert action text into publication authority;
- convert cryptographic integrity or repository presence into factual truth;
- establish PoAI decision-time availability;
- execute a parser/XSS attack;
- create a scalar trust/reputation/compatibility score.
