# Successor sequence after Component Manifest v0.1

The first reusable-tooling slice is metadata-only. The next increments should preserve this order unless new evidence blocks it:

1. **Dependency / Impact Graph v0.1** — resolve typed manifest edges, reverse dependencies and affected conformance commands; read-only only.
2. **Generated Conformance Runner v0.1** — reproduce an existing long predecessor CI chain from manifests before any workflow narrowing.
3. **Receipt Runtime SDK v0.1** — extract canonicalization/hash/frontier/predecessor helpers behind explicit component-owned canonicalization profiles; migrate only after byte-identical differential evidence.
4. **Implementation Substitution Assessment v0.1** — compose Registry, Negotiation, Attestation, Evolution and component/interface metadata into consumer-specific substitutability evidence.
5. Later candidates: Human Decision Gate, Observation/Provenance profile, generic provenance store and bounded interaction lifecycle.

## Promotion constraint

No item in this sequence becomes a new Core primitive merely because it is useful tooling. Core promotion continues to require independent product consumers, cross-product conformance and evidence that extension/profile/tooling placement is insufficient.
