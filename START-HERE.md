# Start Here — UU-AAP / PoAI

**Status:** non-normative participation guide  
**Scope:** navigation and participation only

This page helps people enter the project. It does **not** define protocol semantics, conformance, authority, release status, or canonical state. Canonical anchors remain in `main`; see [`docs/CANONICAL-STATE.md`](docs/CANONICAL-STATE.md).

Prefer a web landing page? Use <https://matawaka.github.io/uu-aap/participate/>.

## You have 5 minutes

Choose one path:

1. **Review without coding** — [Issue #422](https://github.com/Matawaka/uu-aap/issues/422). You do not need to understand the whole repository. One concrete counterexample is enough.
2. **Test the newcomer path** — [Issue #774](https://github.com/Matawaka/uu-aap/issues/774). Follow the public entry path without prior study and report the first friction point.
3. **Smoke-test the PoAI Web Verifier** — [Issue #775](https://github.com/Matawaka/uu-aap/issues/775). Compare one expected-valid and one expected-invalid vector with the public browser result.
4. **Discuss UU-AAP** — [Discussion #8](https://github.com/Matawaka/uu-aap/discussions/8).
5. **Discuss PoAI** — [Discussion #10](https://github.com/Matawaka/uu-aap/discussions/10).
6. **Build or test something else** — browse [`good first issue`](https://github.com/Matawaka/uu-aap/issues?q=is%3Aissue+state%3Aopen+label%3A%22good+first+issue%22) or [`help wanted`](https://github.com/Matawaka/uu-aap/issues?q=is%3Aissue+state%3Aopen+label%3A%22help+wanted%22).
7. **Read first** — [`PRINCIPLES.md`](PRINCIPLES.md), [`SPEC.md`](SPEC.md), and [`proposals/poai/README.md`](proposals/poai/README.md).

Russian-speaking reviewers can start with [`PUBLIC_REVIEW.ru.md`](PUBLIC_REVIEW.ru.md).

## Useful participation

Useful contribution does not have to be code. Examples:

- a concrete failure case;
- a privacy, surveillance, or coercion risk;
- ambiguous or unfair responsibility assignment;
- an interoperability or implementation failure;
- an adoption or usability burden;
- a competing interpretation or model;
- a reproducible bug or test gap.

Agreement is not required. Disagreement is useful.

## Participation boundaries

`participation != endorsement`

`comment != identity proof != authority != standing`

`issue label != protocol status`

`Pages / Wiki / this guide != normative specification`

`release candidate != release`

`external evidence != certification`
