## 2. Current Russian-law boundary

Legal snapshot checked for this gate: 2026-08-25.

For the filing decision, apply the following boundaries conservatively:

1. Under Civil Code Article 1228, the author of a result of intellectual activity is the citizen whose creative labor created the result. A person who provided only technical, consultative, organizational or material assistance, helped formalize rights/use, or merely controlled the work is not an author on that basis alone.
2. Under Article 1261, source text and object code of programs for computers receive copyright protection under the rules applicable to literary works; a program is an objectively expressed set of data and commands intended to make a computer/device produce a result.
3. Under Article 1295, if protected expression was created within an employee's established employment duties, authorship remains with the author but the exclusive right ordinarily belongs to the employer unless a contract provides otherwise.
4. Under Article 1262, voluntary state registration is initiated by the right holder; the application relates to one program/database and identifies the right holder and author (unless the author declines mention) together with identifying deposit materials.

This repository is an evidence system, not a substitute for individualized legal advice or adjudication.

## 4. Human creative-contribution test

For every candidate natural-person author, collect evidence for at least one legally relevant creative contribution category and distinguish it from non-creative support.

### A. Requirements / architecture

Potential evidence:

- contemporaneous messages or notes containing original choices;
- alternatives considered and rejected;
- typed-interface design choices;
- substantive constraints that shaped protected expression.

A high-level idea alone should not be represented as authorship of source-code expression.

### B. Source-code expression

Potential evidence:

- source written directly by the person;
- private drafts/diffs;
- local file history;
- commits attributable to actual creative editing rather than automated generation or mechanical formatting.

### C. Selection / editing / restructuring / integration

Where generative AI was used, identify concrete human choices such as:

- selecting one implementation among alternatives for expressive reasons;
- materially rewriting generated code;
- restructuring logic;
- changing data structures or control flow;
- integrating independently generated fragments through creative choices;
- introducing original error semantics or test vectors.

Approval, merge, or choosing “accept” without evidence of creative selection/transformation is not enough by itself.

### D. Debugging / testing choices

Testing can be relevant when the person creatively designed failure semantics, adversarial vectors, boundary cases or corrections rather than only executing a test command.

## 5. AI-assistance classification

Classify the selected filing scope into one of these operational paths.

### Path H — human-authored source evidenced

Use when a natural person can evidence that they personally created the protected source-code expression, even if ordinary tools or non-generative assistance were used.

Candidate outcome:

`HUMAN_AUTHORED_CODE_EVIDENCED`

### Path HA — AI-assisted human creation evidenced

Use when generative AI participated, but a natural person can evidence sufficient personal creative choices in the protected expression through substantive selection, rewriting, restructuring, correction, integration or other creative transformation.

Candidate outcome:

`AI_ASSISTED_HUMAN_CREATION_EVIDENCED`

Do not reduce this to a percentage-of-code test. Record the actual free creative choices and their effect on the resulting expression.

### Path N — claim narrowing required

Use when some fragments have strong human-authorship evidence and others do not.

Possible treatment:

- narrow the deposited identifying source to rights-cleared/human-authored portions;
- exclude uncertain generated/copied expression where the resulting deposit still identifies one coherent program truthfully;
- keep the full private source package separately for technical provenance.

Candidate outcome:

`AUTHORSHIP_CLAIM_NARROWING_REQUIRED`

### Path U — authorship unresolved

Use when the public repository cannot establish whether a natural person contributed creative protected expression.

Candidate outcome:

`MORE_EVIDENCE_REQUIRED`

Remain in `RIGHTS_REVIEW`.

### Path B — no defensible human authorship established

If the selected source is established to be generated automatically without legally relevant human creative contribution, do not name a person as author merely because that person prompted, supervised, owned the repository or merged the result.

Candidate outcome:

`NO_HUMAN_AUTHORSHIP_ESTABLISHED` or `BLOCKED`.

Before filing, either resolve the legal basis with qualified counsel or select a different rights-cleared software object/scope.

## 6. Employment / commissioning / assignment gate

Before `RIGHTS_CLEARED`, privately answer for the creation period:

- Was the selected protected expression created within established employment duties?
- Was there a specific employer task covering this software?
- Was the work commissioned under a contract allocating exclusive rights?
- Was it created as part of consulting/development services for a customer?
- Was any employer/customer confidential material incorporated?
- Was any exclusive right assigned before or after creation?

Do not commit employment contracts, customer contracts, addresses, signatures or other unnecessary private material. Bind retained private evidence by digest/reference.

- transfer any exclusive right;
- determine whether an AI-assisted result is copyrightable in a disputed factual scenario;
- establish employment or customer ownership;
- file a Rospatent application;
- create patent rights;
