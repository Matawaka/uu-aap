# Core Pilot 001 — Run 001 materialization

This runbook resolves the distinction between immutable pilot origin and the concrete execution target observed immediately before a real continuity run.

```text
pilot_origin != execution_target
permit materialized != capture executed
capture executed != recovery verified
```

## Materialization procedure

1. Observe current canonical `main` commit and tree immediately before authorization.
2. Create a local `run-permit.json` conforming to `run-permit.schema.json`.
3. Bind exact local `continuity_root` and separate disposable `recovery_root`.
4. Set `human_authorized=true` only after reviewing all allowed and forbidden effects.
5. Execute `continuity.py capture` using the permit's exact execution-target commit as `--expected-main`.
6. Verify the emitted continuity manifest with `continuity.py verify`.
7. Clone the emitted bundle into the permit's disposable recovery root and run `git fsck --full`.
8. Compare recovered commit and tree with the permit's execution target and the continuity manifest.
9. Record capture/recovery receipts. Do not push, add a writable remote, or infer canonicality from restored bytes.

The permit should be materialized outside canonical Git history after the execution target is observed; otherwise committing the permit would itself move `main` and make its target stale.
