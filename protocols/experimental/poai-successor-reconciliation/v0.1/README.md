# Legacy PoAI successor reconciliation v0.1

This read-only map reconciles the historical open PoAI Level 3.1 / Level 4 RFC line with the current reusable UU-AAP stack.

It does not rewrite historical RFCs or treat old open issues as current requirements. Each semantic family is classified as `PRESERVED`, `REUSED`, `SUPERSEDED_BY`, `NEEDS_SUCCESSOR`, or `OUT_OF_SCOPE`.

The first map identifies four genuine successor questions rather than reviving the whole legacy roadmap:

1. persistent key continuity as reusable evidence, if still needed;
2. identity evidence that does not collapse account control into identity;
3. scoped authority evidence / issuer entitlement compatible with current Authority/Responsibility semantics;
4. policy-relative materialization/canonicality that composes current successor, contention and registry layers without inventing authority.

Historical review/appeal/adjudication/execution/verification/outcome distinctions remain provenance constraints, but dedicated legacy sidecar families are not automatically promoted into current Core primitives.
