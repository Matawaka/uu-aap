# UU-AAP Licensing

This repository uses a **split open-license model**.

The licensing split below replaces the earlier public-draft licensing proposal and is intended to make reuse rights explicit while preserving attribution, provenance and the distinction between an open fork and the canonical UU-AAP project lineage.

## 1. Non-software content — CC BY 4.0

Unless a file says otherwise, **non-software content** in this repository is licensed under the **Creative Commons Attribution 4.0 International Public License (CC BY 4.0)**.

This includes, for example:

- specification prose and explanatory documents;
- governance, provenance, responsibility and review documents;
- Markdown and other narrative documentation;
- diagrams and explanatory assets created for this repository;
- pilot/example narrative;
- non-executable example manifests, experimental records and evidence documents where no more specific license is stated.

Full license text:

`LICENSES/CC-BY-4.0.txt`

SPDX identifier: `CC-BY-4.0`

## 2. Software and implementation content — Apache-2.0

Unless a file says otherwise, **software and implementation content** in this repository is licensed under the **Apache License, Version 2.0**.

This includes, for example:

- source code and executable tooling;
- scripts;
- test code and test harnesses;
- validators and reference-implementation code;
- GitHub Actions workflow code;
- JSON Schema definitions and other machine-executable implementation definitions.

Full license text:

`LICENSES/Apache-2.0.txt`

SPDX identifier: `Apache-2.0`

## 3. File-specific and third-party material

A file carrying an explicit license notice, SPDX identifier or third-party notice is governed by that more specific notice for that file.

Third-party material is **not relicensed merely because it appears in this repository**. Contributors must only submit material they are authorized to contribute under the applicable terms.

Where classification is genuinely ambiguous and no file-specific notice exists, treat the material as **non-software content under CC BY 4.0** until the repository records a more specific classification.

When CC BY 4.0 material is shared, attribution should preserve, where reasonably practicable and consistent with the license:

- **Project:** `UU-AAP — Augmented Authorship & Accountability Protocol`;

- **Canonical repository:** `https://github.com/Matawaka/uu-aap`;
- a reference to **CC BY 4.0**;
- an indication of modifications when required by the license.

`CITATION.cff` provides machine-readable citation metadata. `NOTICE.md` records project provenance and anti-impersonation/canonical-lineage boundaries.

## 5. Open reuse does not confer canonical status or endorsement

These licenses permit broad reuse within their terms, including commercial reuse where the applicable license permits it. They do **not** make a copy, fork, implementation, publication or derivative work the canonical UU-AAP project or an official successor.

`permission to copy != canonical succession`

`open license != endorsement`

`fork != canonical successor`

`commercial implementation != official implementation`

Nothing in this licensing map grants permission to imply sponsorship, endorsement, official status or canonical-successor status beyond what the applicable license itself permits. The project name may be used in the ordinary descriptive manner needed to identify origin and satisfy attribution; no additional trademark or endorsement rights are granted here.

## 6. Provenance and ownership boundary

Repository history, `NOTICE.md`, checkpoint manifests and protected tags preserve inspectable provenance. They do not by themselves adjudicate copyright ownership, legal identity, legal authority, factual truth or responsibility for third-party actions.

Each contributor licenses only rights they are authorized to license. Acceptance of a contribution does not erase its recorded provenance or make the repository editor the sole author of that contribution.

`attribution != legal ownership adjudication`

`provenance preserved != truth certified`

## 7. Contributions

Intentional contributions are governed by `CONTRIBUTING.md` and the applicable outbound license for the contributed material, unless the contribution is explicitly marked otherwise or a separate written agreement applies.

This repository currently uses an **inbound = outbound** contribution model rather than a separate contributor license agreement.
